SECTION 02

Where is AI Actually Used in the Project?

The exact division of labor between Probabilistic AI (The Brain) and Deterministic Software (The Guardrails).

💡 THE WINNING PHILOSOPHICAL FORMULA:

Traditional software is brittle — it crashes the moment an input format changes or an ambiguous natural language prompt is given.
Raw LLMs are unreliable — they hallucinate on mathematics and cannot be trusted with refinery equipment safety.
Our Solution: We use AI where AI excels (unstructured vision perception, semantic intent decomposition, dynamic Python code synthesis, and executive memo drafting) and deterministic software where software excels (exact IEEE-754 arithmetic, subprocess isolation, cryptographic SHA-256 Merkle hashing, and air-gap socket sniffing).

AI ROLE 1: ROUTING & PLANNING Nodes 1 & 2

Unstructured Natural Language Intent Parsing

Why Code Fails: Traditional software requires rigid command-line flags. If an engineer types free-form text (*"Check the CDU furnace tubes from yesterday's inspection and tell me if we need CGM approval"*), traditional scripts crash.

Where AI is Used: The Poly-Model Router & Step Planner decodes ambiguous intent, detects required domain modalities, and generates the 5-step DAG plan.

AI ROLE 2: VISION SLM (Qwen2-VL) Node 3

Multimodal Scans, Blueprints & P&IDs

Why Code Fails: Refinery documents are often scanned photocopies, noisy handwritten inspection grids, or complex visual P&ID diagrams with crossing piping lines.

Where AI is Used: The Multimodal Vision SLM (`Qwen2-VL`) visually inspects the image, recognizes contextual text, and extracts engineering parameters into structured data.

AI ROLE 3: CODE SLM (Qwen-Coder) Node 4

Dynamic Code & Algorithm Synthesis

Why Code Fails: If an engineer asks for a calculation not pre-coded into a script (e.g. *API 579 crack flaw sizing* or *Heat Exchanger LMTD*), hardcoded scripts fail.

Where AI is Used: The Code SLM (`Qwen2.5-Coder`) writes executable Python calculation scripts on the fly and passes them to our subprocess sandbox.

AI ROLE 4: REASONING SLM (DeepSeek-R1) Node 5

PSU Approval Memo & Policy Synthesis

Why Code Fails: A Python script can only output raw numbers (`6.162` and `5.27`). It cannot write a structured, 3-page formal government PSU memorandum.

Where AI is Used: The Reasoning SLM (`DeepSeek-R1`) synthesizes the technical findings, financial implications, Delegation of Power (DOP) limits, and recommendations into an official Microsoft Word `.docx` note.

📐 The ASME B31.3 Process Piping Engineering Math Gold Standard Formula

t_min = [ (P * D) / (2 * (S * E + P * Y)) ] + c
Input Values (From Field Log): • Pressure (P): 4.0 MPa (40 bar) • Diameter (D): 219.1 mm (8" Pipe) • Stress (S): 137.0 MPa (ASTM A106) • Measured Wall: 7.48 mm
Step 1: Required Minimum: t_nominal = (4.0 * 219.1) / (2 * (137.0*1.0 + 4.0*0.4)) t_nominal = 3.162 mm t_min = 3.162 + 3.0 = 6.162 mm
Step 2: Safe Remaining Life: Safe Margin = 7.48 - 6.162 = 1.318 mm Corrosion Rate = 0.25 mm/year Safe Life = 1.318 / 0.25 = 5.27 Years

Our Solution: Real-time hardware telemetry profiler via `psutil`. If available RAM drops below 1.0 GB, it triggers automatic memory throttling and subprocess memory boundaries.
